# Безопасность и соответствие 152-ФЗ

Документ описывает принятые в MVP решения и то, как они закрывают требования законодательства о
персональных данных и типовые угрозы для сервиса, работающего в мессенджере.

## Модель угроз

| Угроза | Механизм защиты |
| --- | --- |
| Подделка входа в мини-приложение | Проверка HMAC-подписи `initData` на сервере, контроль возраста `auth_date` |
| Подмена номера телефона при «поделиться контактом» | Проверка хеша MAX: для бота — `HMAC_SHA256(token, vcf_info)`, для мини-приложения — `HMAC_SHA256(token, "auth_date=…\nphone=…\nuser_id=…")`, `user_id` берётся из подтверждённой сессии, а не из клиента |
| Перехват трафика | TLS 1.2/1.3, HSTS, проверка цепочки с российским доверенным корневым сертификатом, webhook принимает только HTTPS |
| Подделка событий бота | Заголовок `X-Max-Bot-Api-Secret`, сравнение постоянным по времени, дедупликация событий |
| Кража токена доступа | Короткий срок жизни access-токена (30 минут), хранение только в `sessionStorage`, ротация refresh-токенов с отзывом использованного |
| Подбор и злоупотребление | Ограничение частоты на nginx и в приложении, отдельные лимиты на вход, обновление токена и вызовы наставника, лимит попыток кода привязки |
| Утечка базы | Шифрование телефона и e-mail (Fernet), слепые индексы вместо открытого хранения, хеш IP в журнале, минимальный состав данных |
| Утечка данных во внешний ИИ-сервис | Обезличивание текста до отправки в GigaChat, восстановление только имён, отдельное согласие на автоматическую обработку |
| Доступ к чужим данным | Проверка роли и принадлежности на уровне сервиса: задачи видит только ученик, дайджест — только родитель ребёнка, аналитика — педагог и администратор |
| Инъекции и XSS | Параметризованные запросы SQLAlchemy, экранирование в React (без `dangerouslySetInnerHTML`), CSP nginx и API |
| Раскрытие внутренностей при ошибке | Единый структурный формат ошибки без стека, `/docs` и `/openapi.json` отключены в production |

## Аутентификация и сессии

**Вход.** Единственный способ входа — стартовые данные MAX. Сервер восстанавливает `launch_params`
из отсортированных параметров, вычисляет
`secret_key = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)` и
`sig = HMAC_SHA256(key=secret_key, msg=launch_params)`, сравнивает `sig` с `hash` постоянным по
времени и проверяет, что `auth_date` не старше `MINIAPP_AUTH_WINDOW_SECONDS`. Дубликаты ключей и
лишние `hash` отклоняются.

**Токены.** Access-токен — JWT HS256, 30 минут, содержит `sub` (UUID пользователя), `role`, `jti`.
Refresh-токен — 14 дней, его `jti` сохраняется в `auth_sessions` вместе с хешем IP и user agent;
при обновлении прежняя запись отзывается и создаётся новая. Выход отзывает сессию. Просроченные
сессии отзываются worker'ом и командой `app.cli expire-sessions`.

**Роли.** `guest` — вход выполнен, но роль не подтверждена; `parent` — после подтверждения привязки
к обучающемуся; `teacher` и `administrator` — назначаются оператором (`app.cli grant-role`).
Проверка роли выполняется и в токене, и по записи в БД: расхождение приводит к требованию
повторного входа.

**Клиентская часть.** Токены хранятся в `sessionStorage` и не попадают в URL и логи. Запросы уходят
на тот же домен по пути `/api/`, CORS в боевой схеме не используется.

## Криптография и защита данных

| Данные | Как хранятся |
| --- | --- |
| Телефон, e-mail | Шифртекст Fernet (`FIELD_ENCRYPTION_KEY`) + слепой индекс HMAC (`SECRET_KEY`) для поиска и контроля уникальности |
| IP-адрес в журнале | HMAC-хеш с префиксом, обратное восстановление адреса невозможно |
| Код привязки ребёнка | Только слепой индекс, исходный код не сохраняется, отправляется один раз |
| Пароли | Отсутствуют как класс: вход только через MAX |
| Refresh-токены | Только `jti` и метаданные сессии |
| Содержание учебных диалогов | Текст в БД, метки тем и итоги — без исходных персональных данных |

Ключи `SECRET_KEY` и `FIELD_ENCRYPTION_KEY` — не менее 32 символов; в `production` запуск с
короткими или пустыми ключами прерывается. Ключи не логируются: редктор structlog заменяет
значения по списку чувствительных ключей (`token`, `authorization`, `phone`, `email`, `hash`,
`initdata`, `max_bot_token`, `gigachat_credentials` и др.) на `[redacted]`.

Ротация `FIELD_ENCRYPTION_KEY` требует перешифрования полей: процесс описан в
[docs/personal-data.md](personal-data.md).

## Транспорт и периметр

- nginx: TLS 1.2/1.3 с современным набором шифров, отключённые сессионные билеты,
  `server_tokens off`, HSTS на два года с preload, HTTP → HTTPS.
- CSP мини-приложения: `default-src 'self'`, скрипты только со своего домена и `https://st.max.ru`,
  `connect-src 'self' https://*.max.ru`, `frame-ancestors https://max.ru https://*.max.ru`,
  `object-src 'none'`, `base-uri 'none'`.
- API отвечает `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`, `Permissions-Policy` с закрытыми геолокацией, микрофоном, камерой
  и платежами, `Cross-Origin-Opener-Policy` и `Cross-Origin-Resource-Policy: same-origin`,
  `Content-Security-Policy: default-src 'none'`.
- `limit_req`: 30 r/s на `/api/` с burst 60 и 5 r/мин на `/api/v1/auth/max` с burst 10.
- Контейнеры запускаются непривилегированным пользователем `app` с `no-new-privileges`, база
  доступна только из внутренней сети compose, наружу опубликован лишь nginx.
- Обращения к MAX и GigaChat выполняются с проверкой цепочки доверия; при необходимости указывается
  `MAX_CA_BUNDLE` / `GIGACHAT_CA_bundle` с корневым сертификатом Минцифры.

## Ограничение частоты

Глобальный лимит `RATE_LIMIT_PER_MINUTE` применяется к изменяющим запросам, отдельные корзины
действуют для входа (10 попыток в минуту на IP) и обновления токена (30 в минуту). Ассистент
ограничен `AI_RATE_LIMIT_PER_HOUR` на пользователя. Превышение возвращает 429 со структурой ошибки
и событием в журнале.

## Аудит

`audit_events` фиксирует: вход и отказы во входе, предоставление и отзыв согласий, публикацию
редакций документов, операции с персональными данными (выписка, прекращение обработки, удаление),
создание и изменение задач, назначение ролей, привязку родителя, доставку уведомлений.
Каждая запись содержит субъекта (или признак анонимного запроса), действие, объект, результат, хеш
IP, user agent и метаданные. Срок хранения — `AUDIT_RETENTION_DAYS` (по умолчанию 1095 дней),
очистку выполняет worker и команда `app.cli retention`.

Журнал доступен субъекту данных в обезличенном виде через выписку `GET /api/v1/me/personal-data`.

## Обезличивание перед отправкой в GigaChat

Перед внешним вызовом текст диалога проходит `PersonalDataRedactor`. Распознаются и заменяются
масками: `EMAIL`, `СНИЛС`, `ПОЛИС`, `ИНН`, `ПАСПОРТ`, `ДАТА_РОЖДЕНИЯ`, `ТЕЛЕФОН`, `ФИО`, `ИМЯ`.
В ответе модели восстанавливаются только метки `ФИО` и `ИМЯ`; остальные категории вырезаются, чтобы
восстановленные извне значения не попали в базу и в интерфейс.

Автоматическая обработка текста выполняется только при действующем согласии `ai_processing`; без
него наставник сообщает ученику о недоступности. В метаданных задачи сохраняются модель,
расход токенов, применённые категории и признак отказа модели — это подтверждение объёма
обработанных данных для отчётности.

GigaChat — внешний сервис, поэтому в контур передаётся минимум: текст без идентификаторов, без
имени пользователя, без номера телефона и без данных школы. Передача обезличенного текста
отдельно описана в политике и в согласии `consent_ai`.

## Соответствие 152-ФЗ

| Требование | Реализация |
| --- | --- |
| ст. 6 — согласие на обработку | Согласие запрашивается до начала обработки, фиксируется цель, источник, редакция документа, время и IP; отдельное согласие на автоматическую обработку |
| ст. 5 — цели и объём | Три цели: `service`, `notifications`, `ai_processing`; состав данных ограничен необходимым |
| ст. 5 — минимизация | Имя, язык и идентификатор MAX берутся из стартовых данных; телефон и e-mail — только по действию пользователя; пароли и документы не собираются |
| ст. 9 — отзыв согласия | Отзыв в один экран в кабинете и командой `/stop` в боте; после отзыва обработка прекращается, доступ к разделам закрывается |
| ст. 12, 18(5) — локализация | PostgreSQL и все данные хранятся на сервере в РФ, внешнему сервису передаётся только обезличенный текст |
| ст. 14 — доступ субъекта к данным | Выписка `GET /api/v1/me/personal-data`: профиль, согласия, счётчики, журнал действий |
| ст. 14, 21 — прекращение обработки и удаление | `DELETE /api/v1/me` и `POST /api/v1/personal-data/erasure-request`: обезличивание профиля и содержания диалогов, отвязка детей, блокировка учётной записи, событие в журнале |
| ст. 16 — хранение не дольше цели | `PERSONAL_DATA_RETENTION_DAYS` для содержания диалогов, `AUDIT_RETENTION_DAYS` для журнала, 7 дней для служебных записей событий, 30 дней для очереди |
| ст. 19 — меры защиты | Шифрование полей, слепые индексы, хеширование IP, разграничение доступа, аудит, ограничение частоты, TLS |
| ст. 19 — учёт машинных носителей и контроль | Журнал аудита, `request_id` в каждом запросе, структурированные логи |
| Постановление № 1119 / приказы ФСТЭК | Разграничение ролей, защищённый периметр, отсутствие открытых административных интерфейсов, `/docs` отключён в production |

Юридические тексты (пользовательское соглашение, политика обработки, согласия) хранятся в
`backend/app/legal` с версиями и публикуются в базу командой `app.cli policies`. Изменение редакции
создаёт новую запись: прежние согласия остаются привязанными к той версии, которую видел
пользователь. При смене редакции сервис запрашивает согласие заново.

## Проверки и эксплуатация

- `make lint`, `make typecheck`, `make test` — ruff, mypy (strict), pytest, eslint, tsc.
- Тесты покрывают проверку подписи `initData`, хеш контакта, шифрование и слепые индексы, JWT,
  лимиты, а также сквозные сценарии согласия, обращений и удаления данных.
- Зависимости зафиксированы в `backend/pyproject.toml` и `miniapp/package.json`
  (`package-lock.json`), обновления применяются через пересборку образов.
- Перед публикацией: отозвать и перевыпустить токены MAX и GigaChat, сгенерировать уникальные
  `SECRET_KEY` и `FIELD_ENCRYPTION_KEY`, включить `APP_ENV=production`, настроить резервное
  копирование и мониторинг `GET /healthz`.

## Известные ограничения

- Роли назначаются оператором через CLI, интерфейса администратора в MVP нет.
- Резервное копирование и восстановление обеспечивает инфраструктура (см. `make backup`).
- Проверка статуса оператора в реестре Роскомнадзора и подача уведомления — организационная задача
  школы, сервис её не автоматизирует.
- WAF и антифрод на уровне сети в MVP не применяются, защита ограничена лимитами и проверкой
  подписей.
