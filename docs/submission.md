# Пошаговый план сдачи решения

Дедлайн: **30 сентября, 12:00 по Москве (19:00 по Чите)**. После дедлайна версия фиксируется и не
меняется. Бот обязан оставаться доступным весь период проверки. План рассчитан так, чтобы сдача
произошла за 2–3 часа до срока.

## 1. Перенос кода в репозиторий команды

**Вариант А — с историей коммитов (рекомендуется).** Склонировать текущий репозиторий и залить
ветку с решением в свой репозиторий как `main`:

```bash
git clone https://github.com/BudArts/max_v0.1.git uchusai
cd uchusai
git checkout arena/01a0ecc0-max-v0-1
git branch -m main                       # переименовать в main
# создать ПУСТОЙ репозиторий на GitHub/GitLab команды, затем:
git remote add team https://github.com/<команда>/uchusai.git
git push -u team main
```

**Вариант Б — из скачанного архива (без истории).** Если код получен кнопкой «Download ZIP»:

```bash
unzip <архив>.zip -d uchusai && cd uchusai
git init -b main
git add -A && git commit -m "Учусь.ai: ИИ-наставник школьника в MAX"
git remote add origin https://github.com/<команда>/uchusai.git
git push -u origin main
```

**Проверка перед публикацией (обязательно):**

```bash
test ! -f backend/.env && echo "ок: .env в репозитории нет"
test ! -f backend/demo.sqlite3 && echo "ок: демо-базы нет"
grep -c "BEGIN CERTIFICATE" deploy/certs/russian_trusted_ca.pem   # должно быть 2
git grep -n "dev-only-\|unit-test-" -- "*.py" | head   # только в тестах и .env.example
```

Токен бота и ключ GigaChat в репозитории отсутствуют и не должны в нём появиться. Токен выдан
организаторами и не подлежит самостоятельной замене (административного доступа к боту нет) — если
он случайно утечёт, сразу писать организаторам. В презентацию и скриншоты токен не попадает.

Репозиторий можно оставить приватным; тогда ссылка на него прикладывается к решению на случай
дополнительной проверки, а основной канал передачи — архив с контрольной суммой (шаг 6).

## 2. Сервер и HTTPS

Требования: VPS 2 vCPU / 2–4 ГБ RAM / 20 ГБ диска, Ubuntu 22.04+. Рекомендуется хостинг в РФ —
это одновременно закрывает требование 152-ФЗ о локализации баз данных.

```bash
ssh root@<IP-сервера>
curl -fsSL https://get.docker.com | sh    # Docker + Compose plugin
git clone https://github.com/<команда>/uchusai.git && cd uchusai
```

HTTPS обязателен (пункт 3 FAQ), домен — нет: подойдёт технический адрес хостинга, если он отдаётся
по HTTPS. Если берёте свой домен — направьте A-запись на сервер и выпустите сертификат Let's
Encrypt (раздел «Сертификаты» [deployment.md](deployment.md)), скопировав `fullchain.pem`,
`privkey.pem`, `chain.pem` в `deploy/certs/`.

## 3. Запуск сервиса

```bash
cp .env.example .env
nano .env
```

Боевые значения в `.env` (отличия от локального профиля):

| Переменная | Значение |
| --- | --- |
| `MAX_BOT_TOKEN` | токен выданного бота — единственный доступ к боту (админ-настроек нет) |
| `APP_ENV` | `production` |
| `APP_DOMAIN` | домен из шага 2 |
| `APP_BASE_URL` | `https://<домен>` |
| `SSL_ENABLED` | `true` |
| `HTTP_PORT` / `HTTPS_PORT` | `80` / `443` |
| `MAX_TRANSPORT` | `webhook` |
| `MAX_WEBHOOK_URL` | `https://<домен>/webhook/max` |
| `MAX_WEBHOOK_SECRET` | своя случайная строка |
| `SECRET_KEY`, `FIELD_ENCRYPTION_KEY` | результат `openssl rand -hex 32` (два разных) |
| `POSTGRES_PASSWORD` | своя случайная строка, то же значение внутри `DATABASE_URL` |
| `DEV_LOGIN_ENABLED` | `false` |
| `SEED_DEMO` | `false` |
| `GIGACHAT_ENABLED` / `GIGACHAT_CREDENTIALS` | `true` / ключ авторизации GigaChat |

Поднять и проверить:

Сертификаты НУЦ Минцифры уже в репозитории (`deploy/certs/russian_trusted_ca.pem`); если нужно
обновить их на сервере:

```bash
curl -fsSL -o deploy/certs/root.crt https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
curl -fsSL -o deploy/certs/sub.crt https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt
cat deploy/certs/root.crt deploy/certs/sub.crt > deploy/certs/russian_trusted_ca.pem
rm deploy/certs/root.crt deploy/certs/sub.crt

docker compose up -d --build
docker compose ps                          # все сервисы Up/(healthy)
curl https://<домен>/healthz               # "status":"ok","database":"up"
```

Зарегистрировать подписку на события и проверить бота:

```bash
docker compose exec backend python -m app.cli webhook set \
  --url "$MAX_WEBHOOK_URL" --secret "$MAX_WEBHOOK_SECRET"
docker compose exec backend python -m app.cli webhook info
```

Напишите боту в MAX `/start`: бот спросит класс, попросит принять согласия — после этого можно
присылать задачу текстом или фотографией. Команды меню регистрируются автоматически при старте
контейнера.

## 4. Подключение мини-приложения к боту

Ссылку `https://<домен>/` отправить через [форму организаторов]
(https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/) — сделать это **сразу после запуска**,
привязка выполняется организаторами и занимает время. Кнопка «Личный кабинет» в боте заработает
после их привязки; до этого сценарий бота (сообщения, согласия, уведомления) уже полностью
работает.

## 5. Проверка основного сценария глазами эксперта

Пройти целиком: ученик (любой аккаунт MAX) — `/start`, класс, согласия → фото или текст задачи →
3–4 наводящих вопроса наставника → самостоятельное решение ученика → подтверждение и разбор.
Педагог (роль выдаётся командой ниже): мини-приложение → обзор класса (темы, доли решённых) →
группа риска. Родитель: `/code` у ученика → ввод кода в мини-приложении → недельный дайджест.
Убедиться, что задачи записываются в базу: `docker compose exec backend python -m app.cli me` и
таблицы `tasks`, `task_messages` в PostgreSQL.

Назначение роли педагога аккаунту эксперта:

```bash
docker compose exec backend python -m app.cli grant-role teacher --max-user-id <id эксперта>
```

## 6. Материалы для личного кабинета

Собираются из клона **своего** репозитория, в котором всё закоммичено (`git status` чистый):

```bash
make openapi            # обновить openapi.yaml из кода
git add openapi.yaml && git commit -m "Обновить спецификацию API" && git push
make submit-archive     # uchusai-src.zip + uchusai-src.zip.sha256
```

В личный кабинет загружаются:

1. **Архив исходников** `uchusai-src.zip` и файл контрольной суммы `.sha256`;
2. **Ссылка на репозиторий** команды;
3. **Презентация** (шаг 7);
4. Если форма просит описание API отдельно — указать `https://<домен>/openapi.json` и приложить
   `DATA-API.yaml` и `openapi.yaml` из корня репозитория;
5. Ссылка на работающий сервис `https://<домен>/` и имя бота в MAX (username напечатает
   `docker compose exec backend python -m app.cli me`).

Подать за 2–3 часа до дедлайна и убедиться, что загрузка каждой версии завершилась: после
дедлайна версия фиксируется.

## 7. Презентация

Титульный лист: название решения и одна строка сути («ИИ-наставник для школьников 5–11 классов
в мессенджере MAX: не даёт списать, а доводит до решения»), трек, название команды, состав и роли
участников, город/учебное заведение, дата — по шаблону организаторов, если он выдан.

Слайды презентации решения уже готовы (`Презентация1.pdf`); при доработке опирайтесь на них и на
материалы репозитория:

1. Проблема: школьник застрял на задаче — поздно вечером некому спросить, а готовый ответ учит
   списывать.
2. Решение: бот MAX с ИИ-наставником на GigaChat — наводящие вопросы, OCR фото задачи, контекст
   класса и предмета.
3. Сценарий ученика, кабинеты педагога и родителя — скриншоты (шаг 5 годится как источник).
4. Архитектура — [architecture.md](architecture.md).
5. Безопасность и 152-ФЗ — по [security.md](security.md): согласия с версией документа,
   шифрование чувствительных полей, журнал доступа, выписка и удаление, данные в РФ.
6. AI: GigaChat — сократический режим (фазы start/guide/solved/stuck/offtopic), обезличивание
   текста перед отправкой.
7. **Что реализовано реально, что модельно** (пункт 13 FAQ): реально — бот, OCR, GigaChat, API,
   аналитика, мини-приложения; модельно — данные школы (синтетические), классы формируются
   оператором, интеграция с АИС школы не входит в MVP.
8. Воспроизводимость: `docker compose up -d`, `DATA-API.yaml`, `openapi.yaml`.
9. План развития: больше предметов, интеграция с АИС школы, кабинет администратора, голосовой ввод.
10. Ссылки: репозиторий, сервис, спецификация API.

## 8. После сдачи — не выключать

- Сервис работает весь период проверки: в compose стоит `restart: unless-stopped`, контейнеры
  поднимутся после перезагрузки сервера сами.
- Код на сервере после дедлайна не обновлять — сданная версия зафиксирована; допускается только
  перезапуск тех же образов.
- Раз в день проверять: `curl https://<домен>/healthz`, `docker compose ps`, `make logs`.
- По запросу экспертов: ученик — любой аккаунт MAX; роль педагога назначается командой
  `docker compose exec backend python -m app.cli grant-role teacher --max-user-id <id>`,
  кабинет родителя — привязкой к ученику кодом `/code`.

## 9. Частые ошибки

| Ошибка | Как избежать |
| --- | --- |
| Токен попал в репозиторий или презентацию | Проверка из шага 1; скриншоты делать на тестовых данных без ключей |
| Запуск без сертификата Минцифры | Файл в `deploy/certs/russian_trusted_ca.pem` до `docker compose up` |
| `webhook set` выполнен до выпуска сертификата | Сначала HTTPS, потом подписка — иначе MAX не доставляет события |
| Ссылка в форму отправлена в последний день | Отправлять сразу после запуска: привязка делается организаторами |
| Архив собран из папки без коммитов | `git status` должен быть чистым, затем `make submit-archive` |
| Сервер выключен после сдачи | Решение проверяют в любой момент в течение всего периода оценки |
