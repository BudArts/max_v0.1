# Учусь.ai — ИИ-наставник для школьников в MAX

«Учусь.ai» помогает ученикам 5–11 классов разбираться в математике и физике: школьник присылает боту
фото или текст задачи, а ИИ-наставник на GigaChat не выдаёт готовый ответ, а ведёт наводящими
вопросами до самостоятельного решения и подтверждает результат. Педагог в мини-приложении видит
проблемные темы класса и группу риска «кто систематически застревает», родитель — недельный
дайджест по ребёнку без микроконтроля переписки.

Backend — FastAPI на PostgreSQL, мини-приложения — React (Vite), бот — MAX Bot API, ИИ — GigaChat.
Сервис работает как оператор персональных данных по 152-ФЗ: версионированные согласия (включая
отдельное согласие на ИИ-обработку), шифрование чувствительных полей, журнал действий, выписка и
отзыв согласия в один экран. Для исходящих вызовов MAX и GigaChat используются сертификаты НУЦ
Минцифры (каталог `deploy/certs`).

## Сценарии

**Ученик** регистрируется в боте, указывает класс, принимает согласия и присылает задачу текстом
или фотографией (текст распознаётся Tesseract). Наставник ведёт диалог 3–5 шагов, после
самостоятельного решения ученика даёт эталонный разбор. История задач доступна в мини-приложении.

**Педагог** открывает мини-приложение и видит по своим классам: сколько задач начато и решено,
темы, вызывающие затруднения, и список учеников с тремя и более нерешёнными задачами за неделю.

**Родитель** привязывается к ребёнку кодом из бота (команда `/code`) и получает недельный дайджест:
сколько задач начато и решено, какие темы разбирались, когда была последняя активность.

## Состав MVP

| Блок | Что реализовано |
| --- | --- |
| Авторизация | Вход по `initData` MAX с проверкой HMAC-подписи, пара JWT, ротация refresh-токенов, отзыв сессий |
| Роли | `student`, `parent`, `teacher`, `administrator`; выбор роли кнопками при первом сообщении боту, смена командой /role и в кабинете |
| Наставник | Сократический диалог на GigaChat (фазы start/guide/solved/stuck/offtopic), запрет готовых ответов, учёт класса и предмета, OCR фотографий |
| Задачи | История задач с тредом диалога, статусы, статистика ученика, недавние темы |
| Аналитика педагога | Обзор по классам (темы, доля решённых), группа риска |
| Кабинет родителя | Привязка по коду (6 цифр, 30 минут, до 5 попыток), недельный дайджест |
| Бот MAX | Команды меню, приём фото и текста, согласия по кнопкам, /code для родителя, /stop |
| 152-ФЗ | Версионированные документы, отдельное согласие на ИИ, выписка по данным, отзыв, удаление, аудит, сроки хранения |
| Эксплуатация | Docker Compose (API, worker, PostgreSQL, nginx), Alembic-миграции, CLI, health-проверка, структурированные логи |

## Запуск

Разовая подготовка — скопировать `.env.example` в `.env` и вписать `MAX_BOT_TOKEN`
(и `GIGACHAT_CREDENTIALS`, если нужен наставник). Дальше все локальные компоненты
(API, worker, PostgreSQL, nginx, мини-приложение) поднимает одна команда:

```bash
docker compose up -d --build
```

Сборка занимает 2–4 минуты, работы на `http://localhost:8080`. После старта backend сам применяет
миграции, публикует редакции документов и наполняет демо-данные (классы 7А и 8А, задачи, родители).

Остановка, перезапуск, журналы:

```bash
docker compose down
docker compose up -d
docker compose logs -f backend
curl -s http://localhost:8080/healthz
```

Подробности — [docs/quickstart.md](docs/quickstart.md), пошаговая сдача —
[docs/submission.md](docs/submission.md), описание API — [docs/api.md](docs/api.md).

## Переменные окружения

Полный список со значениями по умолчанию — [.env.example](.env.example). Ключевые:

| Переменная | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | токен бота MAX, единственное обязательное значение |
| `MAX_TRANSPORT` | `polling` (без публичного адреса), `webhook`, `disabled` |
| `GIGACHAT_CREDENTIALS` | ключ GigaChat; без него бот и кабинеты работают, а на шаге задачи сообщает, что ИИ-наставник недоступен |
| `GIGACHAT_ENABLED` | включение вызовов GigaChat |
| `DATABASE_URL` | строка подключения PostgreSQL |
| `SECRET_KEY`, `FIELD_ENCRYPTION_KEY` | ключи подписи JWT и шифрования полей |
| `DEV_LOGIN_ENABLED` | демо-вход в кабинеты без MAX, только для `APP_ENV=development` |
| `SEED_DEMO` | заполнение демо-данных при старте |
| `HTTP_PORT`, `HTTPS_PORT`, `SSL_ENABLED` | публикация nginx |
| `AI_RATE_LIMIT_PER_HOUR` | лимит обращений к GigaChat на ученика |

## Тестовые данные

При `SEED_DEMO=true` и `APP_ENV=development` создаются две школы-класса (7А и 8А) с классными
руководителями, родителями и учениками, а также задачи с диалогами. Демо-пользователи видны в
демо-входе на главной странице мини-приложения: у ученика `max_user_id=9100101`, у классного
руководителя 7А — `9000000`, у родителя — `9100001`. Все данные синтетические. Повторное
заполнение с очисткой: `docker compose run --rm backend python -m app.cli seed --force`.

## Проверка основного сценария

1. Открыть MAX, найти бота, нажать «Начать» — бот отвечает и предлагает выбрать роль.
2. Выбрать «Ученик», затем класс (5–11), принять согласия кнопками.
   Ожидаемо: бот подтверждает регистрацию и просит прислать задачу.
3. Отправить боту текст или фото задачи (фото — печатный текст, контрастное).
   Ожидаемо: наставник задаёт первый наводящий вопрос, готовый ответ не присылает.
4. Ответить на 3 и более наводящих вопросов.
   Ожидаемо: на каждой шаге короткая подсказка; после самостоятельного решения — подтверждение
   и эталонный разбор.
5. Отправить `/code` — бот пришлёт шестизначный код привязки родителя.
6. Вход родителем или педагогом: открыть «Личный кабинет» из меню бота либо главную страницу
   мини-приложения (демо-вход). Родитель вводит код из шага 5 в разделе «Дети» — появляется
   ребёнок с недельным дайджестом. Педагог видит обзор классов, темы и группу риска.

При ошибке распознавания фото бот просит прислать текст условия; проверка продолжается без
перезапуска. При исчерпании часового лимита GigaChat бот сообщает об этом и предлагает повторить
позже.

## Известные ограничения

- OCR рассчитан на печатный текст; рукописные задачи распознаются хуже — предусмотрен ввод текстом.
- Наставник намеренно не выдаёт готовый ответ до попыток ученика.
- `GIGACHAT_API_PERS` ограничен частотой запросов; лимит настраивается `AI_RATE_LIMIT_PER_HOUR`.
- Демо-вход в кабинеты работает только при `DEV_LOGIN_ENABLED=true`; для публичного контура
  выключается без изменения кода.
- Celery и Redis из презентации не входят в MVP: фоновые задачи выполняет асинхронный worker,
  очереди и кэш — внутри приложения.
